Avant de commencer

Ce guide s'adresse à vous, propriétaire de MbeukChurch — aucune compétence technique n'est requise, suivez simplement les étapes numérotées dans l'ordre.

⚠️ Sécurité — à lire avant tout Ne collez JAMAIS votre clé Hub (elle commence par mbs_) dans un chat, un email, un ticket de support ou une capture d'écran. Elle ne doit exister que dans Vercel (Environment Variables) et, en local, dans un fichier .env.local qui n'est jamais envoyé sur GitHub.

A. Votre SaaS est déjà déployé mise à jour

  1. Récupérer le nouveau code. Si votre projet est sur GitHub : remplacez le contenu du dépôt par les fichiers de ce ZIP (gardez votre historique Git, ajoutez juste les fichiers modifiés/ajoutés), puis : 
    git add .
git commit -m "Connexion au Hub Central MbeukTechnologies"
git push origin main
    Sinon (déploiement par upload manuel sur Vercel) : re-uploadez l'intégralité du dossier de ce ZIP (sans le dossier node_modules s'il existe).
  2. Ajouter les variables d'environnement sur Vercel — allez dans votre projet Vercel → Settings → Environment Variables, puis ajoutez (voir détails ci-dessous) :
    NomExemple
    MBEUK_HUB_URLhttps://hub.mbeuktech.com
    MBEUK_HUB_API_KEYmbs_••••••••••••••••
    MBEUK_PRODUCT_IDuuid-du-produit
    Cochez les environnements Production, Preview et Development.
  3. Ne jamais committer de secret. Le fichier .env.example livré ne contient que les noms des variables, jamais de vraie valeur — c'est normal et voulu.
  4. Relancer le déploiement. Si vous avez poussé sur GitHub, Vercel redéploie automatiquement. Sinon, dans Vercel → Deployments → bouton Redeploy sur le dernier déploiement.
  5. Effectuer les tests de fumée — voir la section Tests plus bas : créer un compte, se connecter, mot de passe oublié, essai gratuit, quota d'appareils, réabonnement, cloud, vidage du navigateur.
  6. Rollback rapide si problème. Dans Vercel → Deployments, retrouvez le déploiement précédent (celui d'avant cette mise à jour) et cliquez sur "Promote to Production" (ou l'équivalent "Rollback"). Vos utilisateurs reviennent instantanément à l'ancienne version le temps de corriger.
  7. Nettoyage de l'ancien système — uniquement après avoir validé que tout fonctionne en production, voir la checklist dédiée plus bas.

B. Votre SaaS n'est pas encore déployé premier déploiement

  1. Créer le projet sur Vercel. Sur vercel.com/new, importez votre dépôt GitHub (ou uploadez ce dossier directement si vous n'utilisez pas Git).
  2. Configuration du framework. Vercel détecte automatiquement Vite ; vérifiez simplement :
    RéglageValeur
    Framework PresetVite
    Build Commandnpm run build
    Output Directorydist
    Install Commandnpm install
    Le dossier api/ (routes Hub) est détecté automatiquement par Vercel comme fonctions serverless — rien à configurer.
  3. Renseigner les 3 variables Hub AVANT le premier déploiement — voir la section Variables ci-dessous. Sans elles, l'app affiche un message "configuration manquante" au lieu de planter silencieusement — mais l'auth ne fonctionnera pas tant qu'elles sont vides.
  4. Premier déploiement — cliquez sur Deploy. Vercel construit puis met en ligne votre site sur une URL du type votre-projet.vercel.app.
  5. Lier votre domaine (optionnel) — dans Vercel → Settings → Domains, ajoutez votre nom de domaine (ex. mbeukchurch.com) et suivez les instructions DNS affichées.
  6. Tests de fumée — voir la section Tests.
  7. Checklist "go-live" :
    • Migration 023 appliquée sur le Hub
    • Clé mbs_... créée avec les scopes auth:*, licenses:verify
    • product_id du produit MbeukChurch copié depuis le Super Admin Hub
    • Les 3 variables sont bien renseignées dans Vercel (Production)
    • Un compte de test a pu créer un essai gratuit et se connecter

Variables d'environnement

Ces 3 variables sont obligatoires et doivent être saisies côté serveur uniquement (Vercel / .env.local) — jamais dans le code.

VariableDescriptionOù la trouver
MBEUK_HUB_URLURL du Hub Central, sans / finalFournie par MbeukTechnologies
MBEUK_HUB_API_KEYClé secrète mbs_...Super Admin Hub → API Keys
MBEUK_PRODUCT_IDUUID du produit "MbeukChurch"Super Admin Hub → Produits
Ne préfixez jamais ces noms par VITE_ ou NEXT_PUBLIC_ Un tel préfixe les ferait fuiter dans le code envoyé au navigateur de vos utilisateurs — la clé mbs_... deviendrait publique.

En local (développement)

Créez un fichier .env.local à la racine du projet (déjà ignoré par Git) en copiant .env.example et en renseignant les vraies valeurs :

cp .env.example .env.local
# puis éditez .env.local avec vos vraies valeurs

Tests après déploiement

Parcours utilisateur

  • Créer un compte (email + mot de passe)
  • Essai gratuit démarré automatiquement (1 appareil)
  • Se déconnecter puis se reconnecter
  • Mot de passe oublié → email reçu avec un nouveau mot de passe
  • Vider les données du navigateur → reconnexion → licence retrouvée (pas de nouvel achat exigé)

Paiement & appareils

  • Bouton "Réabonner" → redirection vers la page de paiement Chariow
  • Code promo appliqué correctement au paiement (si utilisé)
  • Retour après paiement → accès rétabli, même compte
  • Connexion sur un 3ᵉ appareil (si max_devices=2) → écran quota → révoquer un appareil → reconnexion réussie
  • Mode hors-ligne → l'app reste utilisable (cache local, 5 jours de grâce)

Nettoyage de l'ancien système après validation prod

À faire uniquement après avoir confirmé, en production, que la connexion / l'essai / le réabonnement fonctionnent avec le Hub.
  • Retirer l'ancien projet Supabase central d'authentification (celui utilisé pour les tables licenses / user_licenses / user_devices) — conservez une sauvegarde avant toute suppression
  • Ne DROP les tables licenses, user_licenses, user_devices qu'après confirmation explicite que plus aucun utilisateur n'a besoin de l'ancien système
  • Vérifier qu'aucun lien statique "Acheter une licence" (BUY_LINK) n'est plus utilisé ailleurs (emails, réseaux sociaux, site vitrine)
  • Informer vos utilisateurs actifs du changement si leur compte allait changer d'email/mot de passe (normalement non nécessaire — le Hub réutilise le même compte)
Cloud Central IA (point d'attention technique) Deux fonctions premium optionnelles (assistant IA "Claude Central" et emails Brevo "Cloud Central") utilisaient l'ancienne session Supabase pour s'authentifier auprès d'une Edge Function. Elles nécessitent une petite adaptation côté Edge Function pour accepter la nouvelle session du Hub — voir HUB_INTEGRATION.md section 5 pour le détail technique à transmettre à votre développeur.
